## Improvements

**api agent**
- Issue template gains three lines: the ADR lands as `Status: Accepted` with its number reserved in the issue body; tests that read `recordings/` live in a Node package, never `packages/domain`; a brief that parses a command string or lifts an external shape states the parsing model and the out-of-scope cases and is dispatched on the top model. Files: `.claude/agents/planner.md`, root `AGENTS.md` Tests bullet.
- `.claude/agents/implementor-*.md`: the hook runs `$CLAUDE_PROJECT_DIR`'s copy of `scripts/pre-commit-check.sh`, so a PR that edits the hook cannot observe its own change; say so in Verified instead of probing. And: after `gh pr ready`, stop; the controller relays the verdict.
- The controller reads every file a brief cites before quoting it.
- Netlify CLI login on the owner's machine so a failed preview log is readable without the owner.
- One `run:` line in `.github/workflows/ci.yml` for `scripts/pre-commit-check.test.sh`, if the owner wants the hook proven in CI.

**ingest agent**
- `.claude/agents/implementor-*.md`: a PR stays draft until its Verified section is written; poll the verdict in one foreground loop; after a controller ruling, post it on the PR before re-adding `in-review`.
- `.claude/agents/planner.md`: a comment or doc sweep is briefed as "dump every line and read it", grep only as the final check; touch lists name where tests live; every number in an issue body is measured or absent.
- `.claude/skills/load-race/SKILL.md`: the mutating `ssh` step runs from the owner's shell with the `!` prefix; the agent packs the tarball, hands over the exact command, and verifies afterwards.
- Railway api service: add `packages/db` to its watch paths (or trigger the api deploy from db changes), else migrate-on-deploy never runs a migration that arrives without an api change. Needs an `api` issue.
- `apps/api/src/projector/session-picker.ts`: docstring still says ingest upserts every session row; one-line fix on the api track.

**web agent**
- `.claude/agents/implementor-web.md` (and the api and ingest twins): open the PR as a draft without the label; add `in-review` together with `gh pr ready` once `## Verified` holds a real result; each slice's comments and tests describe only what exists at that slice; poll verdicts with a bash loop, never a Monitor; an `in-progress` issue is someone's claim, ask before taking it.
- Root `AGENTS.md` per-task loop: the same label-timing sentence, since every brief quotes that paragraph.
- `.github/pull_request_template.md`: one sentence in the Verified comment that the bot reviews the body as soon as the label lands, so a placeholder costs a round.
- `.claude/skills/rehearse-race/SKILL.md`: one line that the api binds 3000 and the web proxy hard-codes it, so one rehearsal per machine until the port is per-worktree; an `api` issue for a per-worktree api port from `scripts/db-env.sh` with the Vite proxy reading it.
- `.claude/agents/planner.md`: a stacked brief puts a test helper or doc bullet in the slice that first needs it, never a later one; the controller reads a command out of `package.json` on `origin/main` before quoting it.
