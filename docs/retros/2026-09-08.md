# Retro — 2026-09-07 to 2026-09-08

Period: scaffold through the first agent-implemented wave (per-app AGENTS.md files). Ten PRs merged.

## Went well

- The loop itself ran end to end on #10, #11, #12: agent in a worktree → PR with the four lines → task review → one fix round each → scoped re-review → owner merge. Each review found exactly one Important issue and the fix round closed it.
- Guardrails caught real defects before merge: typecheck caught a silent sed failure (#6), the ADR immutability check exists because review found sed-edits bypassed the Edit hook (#2), and the PR-body hook rejected template placeholders on its own first use (#2).
- Decisions landed as ADRs in the same PR as the change that needed them (#6 with ADR-0003) or ahead of it (#8, ADR-0004 before the db package).
- The GitHub Action reviewer found a genuine gap in ADR-0004 (Prisma Migrate cannot run over a transaction-mode pooler) that two humans and one agent had missed (#8).

## Went wrong

- **Docs moved twice, references chased twice** (#2): ADRs went to a top-level folder, then under `docs/`, each time touching every reference and the hook path. Cause: folder layout decided after files referencing it existed.
- **Hooks trusted things they should not** (#2, #14): the `if` filter did not prevent the hook body from running on unrelated Bash calls; the command-string check let `--body-file` and template placeholders through; the commit gate `cd`'d to the main checkout and typechecked the wrong tree for worktree agents. All three found by review or probe, not by the author.
- **Rename contradicted an Accepted ADR without superseding it** (#6): the hook guards editing an ADR, not contradicting one. Fixed by ADR-0003 plus seam-reviewer item 6.
- **Friction lines say "none" on PRs that had a fix round** (#10, #11, #12): implementers wrote the body before review and never updated it, so the record hides that each AGENTS.md needed one round. Related: all three compressed a paste-ready fact from the issue body (vocabulary punted downstream; config-names bullet rewritten; tsconfig enforcement dropped) — same failure shape three times, so the cause is the brief, not the agent.
- **Unverified claim shipped** (#13): whether the app token can submit an approving review was unknown at merge; the next PR's run is the test.
- **Template not followed** (#1, #7): both predate the template. No action.

## Try next time

- `AGENTS.md` §How work is tracked: "after a fix round the implementer updates the PR's Friction line before re-review" — applied in this commit.
- `AGENTS.md` §How work is tracked: issue bodies quote facts that must appear verbatim; a paraphrase of a quoted fact is a review finding — applied in this commit.
- Decide folder layout before writing files that reference it; when a move is unavoidable, one PR moves and re-references in the same commit — recorded here, no file to change.
- Hook scripts are tested by piping the JSON they receive, from both the main checkout and a worktree, before they ship (#2, #14 both had a test gap) — recorded in `scripts/pre-commit-check.sh` and `scripts/check-pr-body.sh` header comments next time either changes.
- Verify #13's approving review on the next PR (packages/db) and record the answer in its Friction line.
