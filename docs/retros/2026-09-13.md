# Retro — 2026-09-13

Period: race day, the Spanish GP (session 11369), and the architecture-review wave filed the same morning (issues #254 to #268; PRs #256, #257, #270, #272 to #277, #279, #280, #282 to #286, #288, #291 to #293). Twenty PRs merged, all bot-approved before the owner merged; three passed on round 1, one took three rounds. The race ran through the released stack from lights out at 13:04 UTC to the flag at 14:38 UTC. This file also lands the 2026-09-11 retro, which was written that evening and never committed.

## Went well

- The pipeline held under a real race. MQTT delivered 37,351 rows with zero drops at 388 rows a minute (`railway logs -s ingest -n 5000 -f 'last 60s'`); Postgres holds 37,542 rows for the session in received order (paged `GET /api/races/11369/events`); the api's cursor was caught up on every one-minute sample.
- The two lanes backed each other up as ADR-0012 intended: REST's only new rows of the race landed on the MQTT lane's two 50-minute token-refresh reconnects (13:14 and 14:05 UTC), and the single writer skipped every duplicate (writer `skipped=0` across 5,000 batches).
- Twenty review-finding PRs merged in one afternoon on three implementor sessions, with no duplicate PR and no ADR-number collision that reached main (#257 renumbered once against an open PR).
- The bot found real defects the implementer missed: a double-counted byte stat caught only by tightening a `toBeGreaterThan(0)` assertion (#288), an undercounted REST stat (#279), `Number(null)` counting an explicit null session key as foreign (#286), a browser-only path breaking a Node fixture test (#274), and a red `e2e` job on a branch it had approved a round earlier (#278), which turned out to be a real regression (#294).
- Verified sections stayed measured: #283 replaced an invisible live A/B with a deterministic store-driven measurement when the simulator's 20x speed collapsed the buffer window; #257 verified the destroy-count check against a matching, a destructive and an unparseable plan.
- Clean round-1 passes came from briefs with exact values and nothing to decide: #273, #277, #293.

## Went wrong

- **ADR discovered in review, seven PRs.** #256, #257, #272, #279, #285, #286 and #288 each had a review round on whether the change needed an ADR or amended one without naming it (a `/health` field, a workflow mechanism, a callback change, a Consequences bolt-on standing in for an amendment). The briefs did not name the ADR the change touched.
- **Stacked bases moved, four PRs.** #276 needed two rebases before any review ran because its base moved twice; #284, #288 and #292 rebased after their bases squash-merged, #288 with a `main.ts` conflict against a sibling that merged first. Every one of these stacked on a branch that still had a review round ahead of it.
- **Briefs citing code they had not read.** #280's decision named two transitions to disable under reduced motion that do not exist in the CSS, and a file outside the touch list; #270 missed an install step visible in the action source the brief pointed at.
- **Live bug, #287.** The projector copies the session row when the fold starts and the lifecycle only restarts it on a key change, so the push said `upcoming` for the whole race and the live page hid the transport bar, align button and connection pill. No rehearsal had ever flipped a session row while the api ran, so nothing could have caught it. The mitigation (an api redeploy) was never run during the race.
- **The recording was not a recording (#289).** The container's jsonl holds 134 lines against tens of thousands of rows because only the REST lane feeds the recorder; the day's MQTT traffic exists only in Postgres and in a local probe capture.
- **Two OpenF1 consumers.** The local POC recorder ran alongside the deployed ingest from 08:17 and both took 429s from 12:31 to 12:33 UTC; stopping the recorder ended them. The POC's `CLAUDE.md` says never to run two, the root `AGENTS.md` only points at it.
- **A retro that was never committed.** The 2026-09-11 retro sat untracked in the main checkout for two days; its improvement items were never applied.
- Smaller: #275 lost a debug round to Node's zlib `flush()` re-entering `write()` with a three-argument call the test mock did not handle; #291 missed one `module.start()` call site that CI's integration job caught; #294 was only visible once #263's buffer bound shipped, so #278's e2e turned red on a rebase that changed nothing in the PR.
