# Retro — 2026-09-09

Period: PRs merged on 2026-09-09 (#85 to #128, 27 PRs). Two owner sessions again: this one on api and ingest, the other on the web track and a simplification pass. Split by area, as yesterday.

## Went well

**api**
- Delta pushes shipped opt-in with ADR-0013 and a measurement (gzipped delta 1.8 KB against 5 KB full state), events-on-push for deep rewind (#115, ADR-0014), the vote cookie for split origins (#117, ADR-0015), and the paged events route (#102). The old full-state stream stays until the web migrates.
- Three production faults were found by reading the live services, not by users, and each was fixed the same afternoon: the deploy break (#118), the wrong next session (#126), and the exporter flood (#128).

**ingest**
- MQTT lane (#105, ADR-0012), fetch-race from OpenF1 (#107: a 2025 race, 21,918 events, export verified), the live entry list with rows tagged by their own session key (#116), and the loader's window guard. The rehearsal with a forced ingest restart mid-drip matched 24,121 rows exactly.
- The OpenF1 token fix (#124) brought the live lanes up for the first time in production; discovery loaded the full 2026 calendar within minutes.

**Frontend**
- Twelve web PRs from the other session: transport bar and time target, polls by race, track status, driver panel, race control feed, lap ticks, alignment on replay, incremental timeline, and a four-lane simplification pass with no behaviour change (#120 to #123).

**Testing**
- CI caught what local fakes could not, again: the tally drift yesterday, and today the stale-diff review on #121 was refuted with `gh pr diff` evidence rather than a rewrite.
- One Postgres per worktree (#99) ended the shared-database pollution from yesterday; no PR today reported it.

**Overall setup**
- Every agent owned its PR through review rounds and polled the bot itself; the owner only merged. Fix rounds stayed under three on every PR except the delta design track.
- ADR numbers were taken at PR-open time and the two collisions that still happened (0011, 0012) were caught by the merge, not by the owner.

**Infra**
- Railway ssh became the operational path: loader, prune, endpoint probes, all from inside the containers with no public database proxy.

## Went wrong

**api**
- The session picker's fallback ("greatest date_start") was written for a one-recording database and picked the December finale once the calendar existed (#126). Cause: the brief's rule did not say what "no live session" means with a full calendar.
- The exporter exported 79 sessions with no timing data the moment the calendar landed (#128). Cause: ADR-0009's "export once when finished" had no precondition on content.
- Delta pushes needed four rounds and two rulings on invariant wording (#109). Design-bearing tracks cost that; the rulings are now ADR text.

**ingest**
- The token guard demanded a number where OpenF1 sends the string "3600", so both live lanes were dead in production from #31 until #124. Cause: the brief lifted the POC's type annotation instead of a measured response. Nobody read the ingest logs for a day.
- The Friday entry-list fetch fired for every past meeting of the year on first discovery (#127). Cause: the rule named a start condition and no end condition.
- Two sessions drove PR #116 at once until a cross-session message settled ownership.

**Frontend**
- Stacked branches conflicted after squash merges again (#104, #110, #111, #115) and two PRs took over branches mid-review from stalled implementers.
- A review on #121 cited a stale diff snapshot and requested changes that did not exist.

**Testing**
- Synchronous fakes hid two more ordering bugs (#120, #123: a ref written in a passive effect instead of during render).
- The retro script printed no rows for today; both retros this week were assembled from `gh pr view` instead.

**Overall setup**
- The pre-commit hook gates the tree at the shell's cwd. The planner's shell resets cwd to the main checkout between calls, so its commits were gated against another session's stale branch and failed twice; the fix landed only through an isolated-worktree agent.
- Two agents each waited 30 minutes for a verdict that never came because they re-labelled the issue instead of the pull request.
- Reviews flagged three "owner decisions" that were really missing ADR text (0012, 0013, 0016); each cost a docs-only round.

**Infra**
- The deploy was broken for the whole morning by #99's wrapper calling git inside an image without git (#118); nobody watched the deploy log after a tooling merge.

## Try next time

- **Read the live logs after every deploy that touches a service.** `.claude/skills/load-race/SKILL.md` gains a "Verify a deploy" step: `railway deployment list -s <service>` shows SUCCESS and `railway logs -s <service> | tail` shows no repeated failure line. Proposed; needs its own small PR.
- **Measure external responses before writing a guard.** `AGENTS.md` §How work is tracked: "A brief that lifts an external API client quotes a measured response, not a type annotation." Proposed; needs its own small PR (AGENTS.md is prose, one line each).
- **Rules name their end condition.** `AGENTS.md` §How work is tracked: "A rule that starts something (a fetch, an export, a retry) names what stops it." Proposed; needs its own small PR (AGENTS.md is prose, one line each).
- **Re-review is the PR label.** `AGENTS.md` §How work is tracked already says so; the agent-loop skill's dispatch template now spells out `gh pr edit <n> --add-label in-review`. Applied in `~/.claude/skills/agent-loop/SKILL.md`.
- **Planner commits go through a worktree agent.** `~/.claude/skills/agent-loop/SKILL.md`: the planner never runs `git commit` from its own shell in a repo whose hook gates cwd. Applied.
- **Decisions get their ADR in the same PR, first time.** `AGENTS.md` §Rules: "A PR that adds a precondition, a config name, or a wire format writes the ADR before asking for review." Proposed; needs its own small PR (AGENTS.md is prose, one line each).
- **Retro script.** `scripts/retro.mjs` printed no rows for a same-day period; issue to file with the reproduction (`node scripts/retro.mjs 2026-09-09` on 2026-09-09 → header only).
- **Stacked PRs.** Yesterday's rule (rebase with `--onto`) held for this session's PRs and not for the other session's; the rule is in AGENTS.md, so the fix is reading it before opening a stacked PR.
