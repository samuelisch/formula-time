# Retro — 2026-09-08, afternoon

Period: from the first retro of the day (PR #15) to PR #78. 40 PRs merged, all server-side tracks of ADR-0001 deployed, the web track built in parallel by a second owner session. Split by area as the owner asked.

## Went well

**Frontend**
- Foundation, board, alignment core, delay nudge, chooser and replay landed as eight small PRs, four with no friction at all (#54, #60, #61, #69). The POC's alignment core ported behaviour-identical with its twelve real-footage fixtures replayed in vitest (#54).
- Replay folds the api's export in the browser with the shared reducer (#70); the same code the projector runs.

**api**
- Projector, fan-out, poll lifecycle, vote path, exporter and races routes shipped as six stacked PRs (#34, #35, #36, #38, #42, #59, #62). Two measurements settled open design questions: a 28k-event race folds in 160 ms at startup, so no chunking; 2,000 concurrent votes land in about 600 ms with exactly one row per viewer.
- The review bot earned its cost: the tick loop without error handling (#34), the rebuild that served an empty state (#34), the poisoned write chain and the void that could resurrect (#35), the same-viewer tally drift (#36, caught by CI), stale polls on every push and the never-voided finished session (#42). Every one was real.

**Ingest**
- REST lane, single writer, static entry list, recording loader and drip simulator (#31, #58, #65, #74, #78). The local rehearsal ran the whole chain end to end on the first attempt: simulator, ingest, fold, stream, poll open, vote counted.
- Both past races loaded into the deployed database and served as exports the same afternoon.

**Testing**
- CI on every PR (#32) turned the Verified section from a claim into a check, and caught a real concurrency bug the local runs missed (#36).
- Test-first held: implementers reported red-then-green on the bug fixes, and reviewers confirmed it from the commit sequence.

**Overall setup**
- Small stacked PRs (owner rule, midday) made every review round a few hundred lines instead of two thousand. Fix rounds took minutes of agent time after the switch.
- Ten ADRs now bind the design; the last five were written in the PR that built the thing (0006 to 0010).

**Infra**
- Railway IaC, migrate-on-deploy, and the Netlify split (#41, ADR-0008) held through a day of forty deploys with no manual dashboard work except the OpenF1 credentials.

## Went wrong

**Frontend**
- Stacked branches after a squash merge conflicted every time the base merged first (#70, #41, #62, #64). Cause: `git merge main` on a stacked branch instead of `git rebase --onto main <old-base>`.
- A fix written on a branch after its PR merged had nowhere to land and needed a cherry-pick PR (#76). Cause: merging before the second review round had posted.
- A modal re-popped after a route remount because dismissal state lived in a singleton and its signature in a per-instance ref (#66).

**api**
- Fakes that resolved synchronously hid two real bugs: the stale poll state on every push (#42) and the same-viewer tally drift (#36). Cause: no test started from a finished session, and no unit test let two promises resolve out of order.
- The first version of the poll wiring existed twice (#42 here, #53 in the other session) because the two sessions did not check each other's open PRs (#47 filed after #42 was open).

**Ingest**
- Four review rounds on #31, all in shutdown and error paths: in-flight tick not awaited, batch lost on a failed insert, malformed session row starving discovery, recorder writing every session every tick. Cause: the brief specified the happy path and left failure handling to the implementer.
- The issue quoted a wrong number (">30,000 events"; the recording holds 28,422) and the rule "a paraphrase of a quoted fact is a finding" turned the brief's own error into a review round (#31).
- The exporter beat the loader and wrote empty export files for both races (#74, found in production). Cause: the loader wrote the session row as `finished` before its events.
- Events loaded from a recording got `seq` in endpoint order, not time order (#78, found by the other session's headless-browser run).

**Testing**
- The shared local Postgres on port 5433 was polluted by concurrent worktrees three times: another branch's migration dropped a column (#65, #74, the rehearsal), leftover poll rows broke a cleanup (#74), and the port itself was held (#58). Every affected agent fell back to a throwaway container, which the briefs had to spell out each time.
- An integration test assumed a gitignored fixture existed in CI (#78).
- A Chrome check required by an issue could only run because an unrelated `playwright` cache existed on the machine (#64).

**Overall setup**
- The review bot needed three workflow fixes in one day (#30, #37, #55): background agents ending the run, cost of the multi-agent plugin on every push, and a security-review report ending the run before the verdict. It also posted findings without a verdict on #33 and #34 in between.
- ADR numbers collided three times (0006 twice, 0007, 0008) because numbers were taken at drafting time while several PRs were open (#31, #41, #43).
- Two owner sessions on one repo produced the duplicate PR above, two ADR collisions, and two agents committing to the same branch at once (#64).

**Infra**
- Railway's Postgres has no public proxy, so loading past races needed an SSH key on the owner's account and a tarball streamed into the ingest container by hand. Nothing in the repo records that procedure.
- The Prisma 7 config and the compose port were both discovered the hard way (#16, #18) and are now in ADR-0005 and the compose file.

## Try next time

- **Stacked PRs rebase, never merge.** `AGENTS.md` §How work is tracked gains: "A PR stacked on another branch is rebased onto main with `git rebase --onto` after the base merges; never `git merge main` into a stacked branch."
- **ADR numbers are taken at PR-open time.** `AGENTS.md` §Rules gains: "Take the next free number from `origin/main` when the PR opens, not when the draft starts; the review bot flags a number already on main."
- **Check the other session before dispatching.** `AGENTS.md` §How work is tracked gains: "Before filing an issue or opening a PR, check open issues and PRs for the same scope; the owner runs more than one session."
- **Failure paths in the brief.** `AGENTS.md` §How work is tracked gains: "The body names the failure paths the deliverable must handle (shutdown, a rejected write, a malformed row) and the test for each; a happy-path-only brief is a review finding."
- **Concurrency needs real interleaving in tests.** `AGENTS.md` §Rules, Tests bullet gains: "a fake that resolves synchronously cannot test ordering; a test of concurrent writes runs against real Postgres or resolves its fakes out of order on purpose."
- **Measured numbers in briefs.** `AGENTS.md` §How work is tracked gains: "A number quoted as an acceptance criterion is measured before it is written, never estimated."
- **Fixture-gated integration tests.** `AGENTS.md` §Rules, Tests bullet gains: "A test that reads `recordings/` (gitignored) is `test.skipIf(!existsSync(dir))`."
- **Merge after the verdict, not before.** `AGENTS.md` §How work is tracked: "the owner merges, after the bot's verdict on the last push".
- **One Postgres per worktree.** Larger: `docker-compose.yml` and the `db:*` scripts derive a project name and port from the worktree. Issue #82.
- **Record the past-race load procedure.** A `load-race` skill under `.claude/skills/` with the SSH steps. Issue #83.
