# Retro — 2026-09-10

Period: PRs merged from 2026-09-10 through the morning of 2026-09-11 (#145 to #204, 49 PRs). The first day the three implementor agents (`.claude/agents/implementor-*.md`) ran the loop themselves from labelled issues; the planner session wrote briefs and rulings, the owner merged. The whole quality wave planned on 2026-09-09 (#129 to #143) closed, plus the three production bugs the owner reported on the 10th and the DNF/DNS ruling. Twenty PRs carried no friction at all.

## Went well

**Routing and throughput**
- Service labels plus one implementor per service turned a fifteen-issue backlog into 49 merged PRs in a day with no duplicate work and no collision between agents on the same file, except the two noted below (#177, #180), both resolved by rebasing.
- The review bot's fix rounds caught real bugs, not style: a stale cache key that kept a prior push's `seq` (#154), a timeline for the wrong session during a session change (#157), seeks closing over render-time state (#159), a false "0.0s" before the first push (#164), a snapshot regressing past a newer frame during gap recovery (#193), a DATABASE_URL ordering bug and a racy assertion in the e2e harness (#199), and an e2e job that never built the workspace packages (#201).
- Re-review reads its earlier verdicts (#147), so later rounds were diffs against the last round rather than fresh audits.

**Data and domain**
- The replay bug the owner reported was root-caused to data, not code: production races loaded before #78 carried endpoint-grouped `seq`. The fix set landed the same day: loader `--replace` with a verify line (#192), export follows the log with ADR-0018 (#178, accepted in #197), and a versioned race-file URL (#189). Lap markers now come from the lap rows' own start time (#203), so "Race start" lands at lights out.
- Lapped gaps survive the reducer (#151) and render (#163); retired cars read DNF and non-starters DNS from a pure domain rule measured against both recordings (#198, #204); ingest tracks race sessions only, with a migration for the rows already written (#195, #196).

**Web**
- Deep rewind on the live page from the browser timeline (#154, #157), the delta stream consumed end to end (#188, #191, #193), the responsive pass at 390 px in three slices (#187, #190, #194), and every polish item from the audit (#170, #172 to #177, #179, #180).
- The Playwright harness and all three ADR-0002 flows exist and run in CI on web changes (#199, #200, #201).

**Maintenance**
- ESLint across the workspace at zero warnings in the hook and CI, with ADR-0017 (#160, #171). Comment sweeps and AGENTS.md refreshes landed for all three apps (#148, #150, #153, #155, #183, #184). `useAligner.ts` is a 140-line composition (#181) and the polls page's settling machine is a hook (#182). The commit gate now matches option-prefixed commits and gates the tree the commit lands in (#152, #156).

## Went wrong

- **Review rounds spent on a placeholder Verified section** (#148, #163, #172, #174): the PR was labelled `in-review` or marked ready before the local check had run, so round 1 flagged "pending" as an unmet criterion. Four re-reviews for nothing.
- **Grep-only sweeps missed vocabulary** (#148 four rounds, #184): a pattern list finds only the labels the author thought of (`issue #N` but not `T6`, case-sensitive and test-file-scoped). The planner's own measurement in the #138 brief undercounted for the same reason, so the brief's number was wrong.
- **Stacked and parallel PRs on one file** (#177 and #173 on `TransportBar.tsx`; #179, #180 and #173 on `ReplayPage.tsx`; #195 left CONFLICTING after a later slice was merged into an earlier branch): every case was resolved with `git rebase --onto`, but each cost a round. The planner reversing the two-PR order of #135 without editing the issue confused the bot on #179.
- **ADR number collision, fourth time** (#178 took 0017 while #171, also 0017, was open and approved): the rule "next free number on origin/main at PR-open time" does not see an open PR's number.
- **Five rounds parsing shell in bash** (#156): each round found one more way a quoted string or a multibyte character moved the cut. The hook works, but the cost says a command-string parser in bash is at its limit; the next hook change should not extend it.
- **Concurrent rehearsals fight over ports** (#172): `pnpm dev:api` waited two minutes for port 3000 held by another agent's worktree. Postgres got per-worktree ports in #82; api and web did not.
- **Tooling gaps found in passing**: `pnpm --filter @formula-time/web lint` does not exist, only the root `pnpm lint` (#172); `gh pr create --draft` returned a non-draft PR once (#164); the poll modal's auto-pop covered the transport bar in e2e flow 3 (#200).
- **Last retro's proposals never landed, and neither did the retro**: the 2026-09-09 retro was written on the evening of the 9th and left as an untracked file in the main checkout; it reaches the repo only in this PR (`docs/retros/2026-09-09.md`). Its three AGENTS.md lines and the load-race "Verify a deploy" step were "proposed, needs its own small PR" and no PR was opened; the retro-script same-day bug was never filed. The review bot caught the missing file on this PR's first round.

## Try next time

- **Ready means verified.** `AGENTS.md` §How work is tracked: "A PR is marked ready, or labelled `in-review`, only once `## Verified` holds the real result; a placeholder there is a review finding." Applied in this commit. The hook enforcing it is #206.
- **Sweeps read, greps locate.** Recorded here, no file: a comment or reference sweep reads every line of the dump it is cleaning; a grep pattern only points at where to start. The planner's briefs quote the command that produced a number, so the implementer can rerun it (`AGENTS.md` §How work is tracked: "A number in a brief carries the command that produced it." Applied in this commit).
- **Slices merge from main, never into each other.** `AGENTS.md` §How work is tracked: "Slices merge into main in order; never merge a later slice into an earlier slice's branch." Applied in this commit. When the dispatch order differs from the issue, the planner edits the issue before dispatching (`~/.claude/skills/agent-loop/SKILL.md`, applied).
- **ADR numbers are checked against open PRs too.** `AGENTS.md` §Rules: "Take the next free ADR number from `origin/main` and from every open PR (`gh pr list --search ADR-00`) when the PR opens." Applied in this commit.
- **Per-worktree api and web ports**, the way `db-env.sh` does Postgres: #207.
- **Retro script same-day period**: #208, with an inclusive end date so a retro can be re-run.
- **Last retro's three lines** (measured responses before a guard, rules name what stops them, the ADR before review) and the load-race "Verify a deploy" step: applied in this commit rather than proposed again. A retro is committed in the session that writes it, before that session ends; `.claude/skills/retro/SKILL.md` step 5 now says so (applied in this commit).
- **Hook parser at its limit.** Recorded here, no file: the next change to `scripts/pre-commit-check.sh` that needs more command-string parsing moves the hook to a small Node script under `scripts/`, tested with vitest like `retro.mjs` will be.
