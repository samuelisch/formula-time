# ADR-0041 — `session_key` is a string on every surface; `RaceFile.schema` becomes 2

- **Status:** Proposed (accepted when this PR merges)
- **Date:** 2026-09-23
- **Owner:** Samuel Chan
- **Amends:** ADR-0009 §1 (the export document's `session` object: `session_key`
  was `11361`, a JSON number; it is now `"11361"`, a string, matching the live
  push).

## Context

Measured 2026-09-22 on main at 9e83fe0: `apps/api/src/projector/projector.ts`
line 61 `sessionAsRawRecord(session)` builds the live push's `state.session`
with `session_key` as a string; `apps/api/src/export/exporter.ts` line 120
`buildDoc` builds the export's `session` object with
`session_key: Number(session.sessionKey)`; `apps/web/src/replay/timeline.ts`'s
`normalizedSessionRow` exists only to turn the export file's number back into
a string so a folded state matches a live one (ADR-0009 §5 "must stay
identical to the server's"). jscpd reported the two api functions as its
largest clone (12 lines, 71 tokens): the eleven-field mapping from a stored
session row to its wire shape was written twice, and the two copies already
disagreed on this one field's type.

## Decision

1. `packages/domain/src/wire.ts` exports `SessionWire` (the eleven fields,
   `session_key: string`) and `sessionToWire(session)`, one mapping from a
   session-shaped row to `SessionWire`, stringifying the key (`String(...)`,
   same result as the existing `.toString()`) and ISO-formatting dates given
   either as `Date` or as an already-ISO string.
2. `apps/api/src/projector/projector.ts`'s `sessionAsRawRecord` and
   `apps/api/src/export/exporter.ts`'s `buildDoc` both call `sessionToWire`
   instead of building the object literal by hand. The two can no longer
   disagree on a field's name or type.
3. `RaceFile.session` is typed `SessionWire`; `RaceFile.schema` moves from
   `1` to `2` so a schema-1 file (the old, number-keyed shape) is
   distinguishable from a schema-2 one on sight.
4. The exporter re-exports a session only when its event log gains a row
   after the last export (ADR-0018); this ADR does not change that, so an
   already-exported session's file stays at schema 1 until its log changes
   and it is re-exported. `apps/web/src/replay/timeline.ts`'s
   `normalizedSessionRow` keeps handling both: a schema-1 file's numeric
   `session_key` is turned into a string; a schema-2 file's is already one
   and passes through unchanged.
5. `apps/web/src/replay/foldRace.ts`'s `foldRace` widens its session
   parameter to `RawRecord | SessionWire`, since `RaceFile.session` is now
   `SessionWire`: a named interface with no index signature, so a caller
   passing a schema-2 file's session straight to the shared, `RawRecord`-typed
   `createTimeline` would otherwise fail to typecheck.

## Consequences

- The live push's `state.session.session_key` was already a string; nothing
  observable changes there.
- A schema-1 file already on disk keeps serving as-is (ADR-0009 §3 disk is a
  cache, not re-generated by this change) until its own re-export
  conditions are met; the web reads either schema without a coordinated
  deploy.
- A future reader of an exported file that assumes `schema` is always `1`
  is a bug from this point on; `schema` must be read, not assumed.
